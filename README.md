# Blue Truth Engine

A CUDA + OpenGL rendering engine. CUDA writes pixels into a Pixel Buffer Object; OpenGL displays it as a fullscreen quad.

## Requirements

- Windows 10/11
- CUDA Toolkit 12.x
- Visual Studio 2022 (includes CMake 3.28)
- NVIDIA GPU (SM 8.0+)

## Build

```powershell
$cmake = "C:\Program Files\Microsoft Visual Studio\2022\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe"

# Configure (downloads GLFW + GLM automatically)
& $cmake -S . -B build -G "Visual Studio 17 2022" -A x64

# Build
& $cmake --build build --config Release
```

## Run

```powershell
# Defaults to assets/scene.xml
.\build\Release\BlueTruthEngine.exe

# Or pass a scene
.\build\Release\BlueTruthEngine.exe assets/scene_anime.xml
```

### Controls

| Key | Action |
| --- | --- |
| `Escape` | Exit |
| `R` | Start / stop recording |
| `C` | Screenshot |
| `D` | Toggle the OptiX AI denoiser |
| `N` | Toggle anime stylization (photorealistic is the default) |
| `V` | Cycle the AOV / radiance-channel debug views |

## Anime stylization

The engine renders photorealistically by default. `N` switches to a stylized
present pass over the *same* converged path-traced data, so the toggle is
instant and does not restart accumulation. Because physical mode aliases all
six radiance channels onto a single buffer, it also costs no extra memory.

Stylization is applied to the converged radiance channels rather than inside
the BSDF, which keeps importance sampling and MIS physically correct and lets
the style ride on real transport: reflections and refractions are banded on the
actual traced result, and outlines are found by ray probes at every path vertex
so they appear correctly *inside* a mirror rather than smeared from the camera.

A style is authored per material and is independent of BSDF type, so a metallic
anime material is just the Disney BSDF with `metallic="1"` plus a metal style.
See `assets/scene_anime.xml` for a commented demo covering cel body tone, a
posterized chrome sphere, and a posterized-refraction gem. The 1-D cel ramp
strips it references are generated by `tools/make_ramps.py`, which documents the
ramp lookup and colour-space conventions.

Environment lighting is a universal feature rather than a stylization one: an
`<environment>` tag takes an equirectangular HDRI, importance-samples it through
the same emitter selection CDF as the mesh lights, and supports an
independently art-directed backdrop.
